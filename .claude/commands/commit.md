---
description: 変更を確認し、ルールに沿ったコミットメッセージ（Jira課題キー付き）を提案する
argument-hint: "[Jiraの課題キー 例: KIDS-12]"
---

コミットの準備をしてください。課題キー：$ARGUMENTS

1. `git status` と `git diff`（ステージ済みは `git diff --staged`）で変更内容を確認する
2. コミット前の確認
   - 秘密情報（.env、鍵、トークン）や子どものデータ（絵、録音、実名、写真）が含まれていないか
   - 無関係な変更が混ざっていないか（混ざっていれば分割を提案する）
   - mainブランチ上にいないか（いる場合はブランチ作成を提案する。形式：`<種別>/KIDS-<番号>-<短い説明>`）
3. コミットメッセージを提案する
   - 形式：`KIDS-<番号> <種別>: <要約>`（種別：feat / fix / docs / chore / ci / test / refactor）
   - 課題キーが未指定なら、ブランチ名から読み取る。分からなければ私に質問する
   - 必要なら本文に「なぜ」を1〜3行
4. ステージするファイルの一覧とメッセージを示し、**私の確認を待つ**
5. 確認が取れたら `git add <ファイル>` と `git commit` を実行する（`git add -A` は使わない）

`git push` はこのコマンドでは行わないこと。
