直前の変更をレビューしてください。対象：$ARGUMENTS（指定がなければ `git diff` と `git diff --staged`、変更がなければ直前のコミット）

次の順で報告してください。

1. **良い点**（具体的に。なぜ良いのかも）
2. **改善点**（重要な順。各項目に「理由」と「直し方のヒント」。答えのコードは、私が求めるまで全部は書かない）
3. **プロジェクトのルールとの照合**
   - 子ども向けデザインのルール（64px、Pointer Events、消音ボタン、トップに戻る、外部通信なし など）
   - コーディング規約（innerHTML不使用、相対パス、ひらがな表記 など）
4. **プライバシーとセキュリティ**
   - 秘密情報（鍵、トークン、.env の中身）が含まれていないか
   - 子どもの実名、写真、絵、録音が含まれていないか
   - 公開環境でサーバーへのアップロードが有効になる経路がないか
5. **学びのポイント**を1つ（C言語、Java、車載開発との比較で）

指摘は事実に基づき、確認していないことは推測と明記してください。コードは変更しないこと。
