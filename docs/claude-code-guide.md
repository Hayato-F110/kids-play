# このプロジェクトのClaude Code設定ガイド

Claude Codeの設定ファイルが「何のためにあり、どう使うか」のまとめ。

## 全体像

| ファイル | 役割 | 車載開発に例えると | Gitで共有 |
|---|---|---|---|
| `CLAUDE.md` | 毎回のセッションで自動的に読まれる、プロジェクトの前提とルール | プロジェクトのコーディング規約と開発計画書 | する |
| `CLAUDE.local.md` | 自分だけのメモ（個人情報、好み） | 個人の作業メモ | しない |
| `.claude/settings.json` | Claudeに許可する操作の範囲（権限） | 診断サービスのアクセス制御 | する |
| `.claude/settings.local.json` | 自分のPCだけの権限設定（確認ダイアログで「常に許可」を選ぶと追記される） | 個人の開発環境設定 | しない |
| `.claude/commands/*.md` | 定型の指示を `/名前` で呼び出す | 定型作業の手順書、マクロ | する |

## CLAUDE.md

- 起動時に自動で読み込まれる。長いほど毎回トークンを消費するので、簡潔に保つ（目安200行以内）
- `@docs/plan.md` のように書くと、そのファイルも読み込まれる。詳細は別ファイルに分ける
- 編集するには：ファイルを直接編集するか、`/memory` を実行して開く
- 同じ指摘を2回したら、CLAUDE.md に書くタイミング

## .claude/settings.json（権限）

判定の優先順位は **deny → ask → allow**。どれにも当たらない操作は、その都度確認される。

| 区分 | 意味 | このプロジェクトの例 |
|---|---|---|
| deny | 常に拒否。Claudeは内容を読めない | `.env`、`*.pem`、`*.key`、`~/.aws/`、`~/.ssh/`、`secrets/`、`data/` |
| ask | 毎回確認する | `git push`、パッケージのインストール、`aws`、`ssh`、Dockerの削除系 |
| allow | 確認なしで実行 | `git status` / `diff` / `log`、テスト、バージョン確認 |

注意点：

- 設定の見本ファイルは `env.example`（先頭ドットなし）にする。`.env.*` を deny しているため、`.env.example` だとClaudeが読めない
- deny はClaudeのツールに対する柵であり、完全な防御ではない。4日目に PreToolUse Hook で二重化する
- 現在の権限は `/permissions` で確認できる
- PowerShell用とBash用の両方のルールを書いている（WindowsではPowerShell、WSLやサーバーではBashを使うため）

## カスタムコマンド

| コマンド | いつ使う | 何をする |
|---|---|---|
| `/start-day` | 1日の最初 | 今日が何日目かを判定し、ゴール・完了条件・作業の順番を示す |
| `/end-day` | 1日の最後 | learning-log と playbook に追記し、進捗と翌日の予定を示す |
| `/review [範囲]` | 作業の区切りごと | 変更をレビューし、秘密情報と子どものデータの混入も確認する |
| `/explain <対象>` | 分からないとき | C言語・MATLAB・Javaとの比較で説明し、確認クイズを出す |
| `/commit [KIDS-番号]` | コミットの前 | 変更を確認し、ルールに沿ったメッセージを提案する。確認後にコミット |
| `/qcd` | 1日の終わり頃 | Claude Codeの使い方をQCDで振り返り、改善点を3つ以内で提案 |
| `/design-prompt <画面>` | Claude Designを使う前 | 貼り付け用のプロンプトを作り、design-prompts.md に記録 |
| `/sec-check` | PRの前、1日の終わり | 秘密情報・子どものデータ・危険なコード・依存関係を確認 |
| `/whats-new` | 週1回 | 新機能を調べ、役立ちそうなものを3つ紹介 |

- コマンドの実体は `.claude/commands/<名前>.md`、または `.claude/skills/<名前>/SKILL.md` の文章。`$ARGUMENTS` に引数が入る
- カスタムコマンドとスキルは統合されていて、どちらの形式でも同じように動き、同じように候補に出る（公式ドキュメントと実機で確認）。`/start-day` だけ試しにスキル形式に移してある。残りは3日目にスキルを学ぶときに揃える
- `/release-notes` のような組み込みコマンドは、Claude Code本体の機能で、カスタムコマンドやスキルとは別物
- VS Code拡張のパネルでは `/release-notes` が候補に出ない（2.1.293で確認）。VS Codeのターミナルで `claude` を起動して実行する
- `/review` が組み込みコマンドと同名で意図どおり動かない場合は、ファイル名を変えて別名にする（例：`kids-review.md`）

### 入力候補に出ないとき（VS Code拡張のパネル）

作った直後のコマンドは、入力候補に出ないことがある（最後まで入力して送信すれば実行はできる）。次の手順で出るようになった（2.1.293で確認。どの手順が効いたかは特定できていない）。

1. `/skills` で一覧ダイアログを開く（絞り込んで、ここから選んで実行もできる）
2. ダイアログを閉じて `/reload-skills` を実行する
3. 数文字だけ入力して候補を確認する（例：`/day`）

## 1日の流れ

1. VS Codeでこのフォルダを開く
2. ターミナルで `claude` を起動（またはVS Code拡張のパネル）
3. `/start-day`
4. 作業（区切りごとに `/review` → `/commit`、話題が変わったら `/clear`）
5. `/sec-check`、`/qcd`
6. `/end-day`
7. 週1回 `/whats-new`
