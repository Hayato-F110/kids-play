# 脅威分析（Threat Model）

初版（2026-10-09）。7日目（2026-10-14）に見直した（4章の「7日目の見直し」）。14日目（2026-10-28）に AWS を片付け、信頼境界4を廃止した（4章の「14日目の見直し」）。構成が変わる日（5日目、10日目、11日目、12日目）にも、該当する脅威を見直す（11日目は4章の「11日目の見直し」）。

- 手法：データフロー図 + STRIDE
- 対象：自分が管理するリポジトリ、アプリ、サーバーのみ

## 1. 保護すべき資産

| # | 資産 | なぜ守るか | 置き場所 | 重要度 |
|---|---|---|---|---|
| A1 | 子どもの絵と声 | 子どものプライバシー。流出すると取り返せない | 端末内（IndexedDB、おえかきの「ほぞん」で作るPNG：ブラウザとPWAはダウンロードフォルダ、Androidアプリ版は `Pictures/AsobiLand`）、localhostのSQLite | 高 |
| A2 | 秘密情報（AWS認証情報、SSH秘密鍵、DuckDNSトークン、署名鍵） | 悪用されるとサーバーの乗っ取りや課金につながる | 自分のPC、GitHub Secrets | 高 |
| A3 | サーバー（EC2）とAWSアカウント | 踏み台や不正利用、高額請求 | AWS | 高 |
| A4 | ソースコードと配布物の完全性 | 改ざんされたアプリが子どもの端末で動く | GitHub、GHCR、GitHub Pages | 中 |
| A5 | 子どもの安全な体験（聴覚、目、不適切な内容に触れないこと） | 大音量、激しい点滅、外部リンクや広告は、子どもに直接の害になる | フロントエンドの実装 | 高 |
| A6 | 開発に使う端末とPCにある、このアプリと関係のない個人のデータ（写真、動画、文書、ほかのアプリの画面） | 失うと取り返せない。開発の道具（adb、シェル）からは、アプリのデータと同じように手が届く | 家族のAndroid端末（内蔵と microSD）、開発用PC | 高 |

## 3. 脅威の洗い出し（STRIDE）

| STRIDE | 意味 | 車載での例 |
|---|---|---|
| **S**poofing | なりすまし | 不正なECUや診断機のなりすまし |
| **T**ampering | 改ざん | CANメッセージやファームウェアの改ざん |
| **R**epudiation | 否認 | 操作の記録が残らない |
| **I**nformation disclosure | 情報漏えい | 鍵や個人情報の読み出し |
| **D**enial of service | サービス拒否 | バスの占有 |
| **E**levation of privilege | 権限昇格 | 診断セッションの不正な昇格 |

STRIDEの当てはめ方（STRIDE per element）：データフロー（矢印）には T・I・D、プロセス（P）には6つすべて、データストア（D）には T・R・I・D、外部の人やサービスには S・R を当てて考える。

| ID | 対象（要素・データフロー） | STRIDE | 脅威シナリオ | 影響する資産 |
|---|---|---|---|---|
| T-01 | P1 フロントエンド、D1 | I、T | 画面に埋め込まれた悪意あるスクリプト（XSS）が、同じオリジンのIndexedDBから絵と録音を読み出し、外部へ送信する | A1 |
| T-02 | DF-08（Claude Code、Claude Design） | I | 指示やデザインの依頼文に、子どもの実名・写真・絵・声を含めてしまい、外部サービスに送信される | A1 |
| T-03 | DF-03（git push）、D3 | I | 秘密情報（.env、鍵、トークン）を誤ってコミットし、公開リポジトリに push する。履歴に残り、削除しても読める | A2、A3 |
| T-04 | D3、P4（依存パッケージ、Actionsの部品） | T | 取り込んだパッケージやGitHub Actionsの部品に悪意あるコードが入り、ビルドした配布物に混ざる（サプライチェーン） | A4、A1、A2 |
| T-05 | DF-04、DF-05（配信） | T、S | 配信の途中で内容を書き換えられる。または、よく似たURLの偽サイトに誘導され、改ざんされたアプリを使う | A4、A1、A5 |
| T-06 | P1（マイク、8日目〜） | I、E | 子どもが意味を分からずにマイクを許可する。許可が残り、意図しない場面で録音が始まる | A1 |
| T-07 | P6（EC2、12日目〜） | S、E、D | SSHへの総当たりや設定の不備からサーバーに侵入され、踏み台や暗号資産の採掘に使われる。高額な請求が発生する | A3 |
| T-08 | DF-10（サーバー保存） | I | 公開環境で、設定の誤りによりサーバー保存が有効になり、絵と録音がサーバーに送信される | A1 |
| T-09 | D1（IndexedDB） | I | 端末を家族以外が使う、または端末を手放すときに、残っていた絵と録音を見聞きされる | A1 |
| T-10 | P1（音、動き、画面の内容） | T（安全への影響） | 不具合や改ざんにより、急な大音量、激しい点滅、外部サイトへのリンクが子どもに届く | A5 |
| T-11 | P7、DF-08、DF-13（AIエージェント） | E、T | Claude Codeが読み込んだ外部の文章（Webページ、他者が作った部品の説明、MCP で読んだ Jira の課題の本文）に指示が埋め込まれ、意図しないコマンドの実行や秘密情報の読み出しにつながる（プロンプトインジェクション）。MCP の道具に書き込みの権限があると、読んだ指示どおりに Jira を書き換えられる | A2、A4 |
| T-12 | D3（リポジトリ） | R | 誰がいつ何を変えたかを追えず、問題のある変更の原因を特定できない | A4 |
| T-13 | P1（おえかきの「ほぞん」）、端末のダウンロードフォルダ（Androidアプリ版は、写真アプリに出る「ピクチャ」） | I | 保存したPNG（子どもの絵）が、端末の設定（写真アプリのクラウド同期、バックアップ）や共有の操作によって、端末の外に出る。アプリの境界の外で起こるので、アプリ側では止められない | A1 |
| T-14 | P1（Service Worker と、端末内の保存場所） | I、T | Service Worker が、残してはいけない応答（10日目以降のAPIの応答など）を端末に保存する。または、古いファイルを返し続けて、修正が端末に届かない | A1、A4 |
| T-15 | P5 GitHub Pages、D1、端末内の保存場所 | I、T | GitHub Pages のオリジン（`<ユーザー名>.github.io`）は、同じアカウントの他の Pages サイトと共有する。端末内の保存場所（IndexedDB、Cache Storage、localStorage）と CSP の `'self'` はオリジン単位なので、別のサイトのスクリプトが、このアプリの絵と録音を読み書きできる。逆に、このアプリの Service Worker が、別のサイトのキャッシュを消す | A1、A4 |
| T-16 | P7（AIエージェント）、開発用PCのシェル、adb、家族の端末 | T、I、E | Claude Code が、開発用PCのシェルから adb を通して、家族の端末を誤って操作する。USBデバッグを許可した端末は、PCからの操作をほぼ無条件に受け入れるので、アプリと関係のないデータの削除、ほかのアプリの操作、端末の画面の撮影ができてしまう。攻撃者がいなくても、エージェント自身の誤り（対象を確かめない削除、画面を見ない操作）だけで起こる。Claude Code の作業フォルダの制限は、ファイルを読み書きする道具にだけ効き、シェルのコマンドには効かない | A6、A1 |
| T-17 | Androidアプリ（Capacitor、WebView）、アプリの中の保存場所、Web から呼べるアプリ側の入口 | I、T、E | アプリの中のデータ（9日目からの絵と声）が、端末のバックアップや機種変更の転送で端末の外に出る。ひな形のままの広い設定（ほかのアプリにファイルを渡す入口、通信の権限）が、使っていないのに残る。えほんの録音のために足したマイクの権限が、録音していないときにも使われる、または通信の権限と組み合わさって声が外に出る。Web の画面から呼べるアプリ側の入口（保存）に、想定していない名前やデータを渡される。リリース版でデバッグ接続が有効のままになり、USB経由でアプリの中を読まれる | A1、A4 |
| T-18 | P3（PC 内の FastAPI）、DF-10 | S、T | 保護者が PC でサーバー保存を有効にしている間に、同じブラウザで開いた別のサイトのスクリプトが、PC 内のサーバーにページを送り込む（CSRF）。multipart の POST は事前の問い合わせなしで送られるので、CORS では止まらない。次に子どもがえほんを開くと、知らない絵と声が紙芝居として流れる。読み出し・削除・上書きは、CORS と事前の問い合わせで止まる | A1、A5 |
| T-19 | DF-14（イメージのビルド）、P10、GHCR（11日目〜） | I | イメージを作るときに、リポジトリのフォルダにある子どものデータ（`data/`、`backend/data/` の SQLite）や秘密情報（`.env`、鍵）がイメージに入る。イメージは GHCR に置かれ、公開のパッケージなら誰でも取り出して中を読める。`.gitignore` はイメージには効かないので、Git で守っていても漏れる。イメージのほかにも、コンテナから子どもや家族の情報が残る場所がある：nginx の一時ファイル（API が断る前に、送られた中身をためる）、アクセスログ（EC2 では家族の端末の IP と User-Agent が残る）、ビルドの記録（build-arg、provenance、レジストリに置くビルドのキャッシュ） | A1、A2 |
| T-20 | P10（コンテナ）、開発用PCと EC2 の docker | E、T | コンテナの中の弱点（nginx や Python の部品の脆弱性）を突かれたとき、コンテナが root や広い権限で動いていると、中身の書き換えやホストへの抜け出しにつながる。また、docker を使えるユーザー（`docker` グループ）は、コンテナを通して実質 root と同じことができる | A3、A4、A6 |
| T-21 | P11（AWS アカウント）、IAM ユーザー | S、E | AWS のサインイン情報（root、または AdministratorAccess を持つ IAM ユーザー）が盗まれ、アカウントを乗っ取られる。EC2 を大量に立てられて高額な請求が発生する、またはサーバーを書き換えられる。AWS の推奨は、人には一時的な認証情報（IAM Identity Center などのフェデレーション）を使うことだが、Identity Center で AWS アカウントの権限を配るには Organizations が要り、無料プランが有料プランに自動で上がるため、長く使う認証情報（IAM ユーザーのパスワード）を選んだ | A3 |
| T-22 | P4（CI）、P11（AWS）、P6（EC2）、DF-06（デプロイ） | E、T | CI（GitHub Actions）の部品の乗っ取りや、ワークフローの書き換えにより、デプロイ用のロールが悪用される。EC2 で root として任意のコマンドを実行される、または改ざんしたイメージに差し替えられる。13日目に自動デプロイ（OIDC と SSM Run Command）を足したことで、新しくできた経路 | A3、A4、A5 |
| T-23 | P6、P11、DuckDNS の名前、DF-06（廃棄の段階） | S、E、I | サーバーを片付けるときの残り物が悪用される。(1) Elastic IP を手放したあとも DuckDNS の名前が同じ IP を指していると、その IP を別の AWS の利用者が受け取ったときに、名前がその人のサーバーを指す（サブドメインの乗っ取り。家族に渡した URL やホーム画面の PWA が、他人のサイトを開く）。(2) 使わなくなったロール、OIDC の信頼、リポジトリの秘密の設定値が残り、あとで別の経路から悪用される。(3) 消し忘れたリソースが料金を発生させ続ける | A3、A4、A5 |

STRIDEの6分類のうち、T-10 は当てはまりが悪い。STRIDEは情報の安全（機密性・完全性・可用性など）の分類で、人への直接の害（聴覚、目）を表す項目がないため。ここでは「改ざん・不具合の結果」として T に置いた（6章の気づきを参照）。
