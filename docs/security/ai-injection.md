# 外部の AI とプロンプトインジェクションの試験（15日目）

2026-10-29。KIDS-60。対象は `tools/ai/`（大人の開発者が PC で使う道具）。子ども向けの画面（`frontend/`）には AI を組み込まない。
脅威と対策の一覧は [threat-model.md](threat-model.md) の T-24〜T-26、C-27〜C-29。

## 1. 作ったもの

| 道具 | 中身 | 外への通信 |
|---|---|---|
| `docs_mcp.py` | `docs/` の `.md` を読むだけの MCP サーバー（道具は `list_docs` と `read_doc` の2つ。stdio） | なし |
| `rag.py` | 公開文書を断片に分けて埋め込み、質問に近い5つを Gemini に渡して答えさせる | Gemini API（無料枠） |
| `evals.py` | 決めた質問と期待する答えで、RAG を自動で採点する。インジェクションの試験つき | Gemini API（無料枠） |

- モデル：生成 `gemini-3.5-flash-lite`、埋め込み `gemini-embedding-2`（768次元）。名前の末尾が `-latest` のモデルは中身が予告なく変わるので、evals の比較には使わない
- 部品：`mcp` 2.3.0、`google-genai` 2.32.0。uv の `exclude-newer` で、公開から7日以上たった版だけにした（T-04）

## 2. 利用規約で確かめたこと（2026-10-29。規約の更新日は 2026-04-28）

- 無料枠では、送った内容と答えが Google のサービスの改善に使われ、人が読むこともある。機密・個人の情報を送らないこと
- 使う人は18歳以上。18歳未満が使う、または使いそうなアプリに組み込まないこと → 子ども向けの画面に組み込まない理由の一つ
- 上限を超えると料金ではなく 429 のエラーになる。請求先は設定していない。埋め込みの無料枠は、1分あたり3万トークン（実際に 429 で確かめた）

## 4. 自作の MCP の試験（C-28、T-26）

Claude Code の deny（`.env` を読まない など）は、Claude Code の組み込みの道具にだけ効き、MCP の道具の中で開くファイルには効かない。そのため、範囲の外を断る処理を道具の側に書いた。

| 呼び出し | 結果 |
|---|---|
| `read_doc("plan.md")` | 読めた |
| `read_doc("../CLAUDE.md")`（Claude Code から） | 「docs/ の外は読めません」で断った |
| `read_doc("../.claude/settings.json")`、`read_doc("C:/Windows/win.ini")` | 断った |

pytest で、`..`、`\` 区切り、絶対パス、`.md` 以外、フォルダー、大きすぎるファイル、断ったときに中身を返さないことを確かめた。シンボリックリンクの試験は、Windows の権限でリンクを作れないため飛ばした。代わりに、管理者の権限なしで作れるジャンクション（フォルダーのリンク）で、`docs/` の外を指すリンクを断ることを確かめた（コードは、リンクを解いてから範囲を確かめる）。

読める範囲は `docs/` の `.md` 全部で、Git の外の下書きも含む。Claude Code の Read でも読める範囲なので新しい経路ではないが、道具の結果は Anthropic に送られるので、`docs/` に個人の情報の下書きを置かない。

## 6. 分かったこと

1. **分かりやすい命令型のインジェクションには、いまのモデルは対策なしでも従わなかった。** 対策（区切りの印と指示）の効果は、「従わない」よりも「見つけて知らせる」に表れた。モデルが変われば結果も変わるので、対策は外さず、モデルや版を変えるたびに evals で確かめる
2. **命令ではない「偽の事実」は、対策なしでは毎回そのまま採られた。** 文書を検索して答える仕組みでは、文書を書き換えられることが、そのまま答えの汚染になる（OWASP LLM04・LLM09）。対策ありで防げたのは、「根拠を示す」「関係のない依頼に応じない」などの指示が効いたためと推測するが、要因を分けた試験はしていない（発展）。根本の守りは、文書に入るものを PR のレビューで止めること（T-25 の前提）
3. **古い情報を根拠に、自信ありげに誤る。** 学習ログは「その日の記録」なので、あとで変わった情報が残る。消すのではなく、「過去の記録」の印と、検索の点数を少し下げることで、いまの仕様を優先させた。×0.9 では別の問題が悪くなり（回帰）、×0.95 で落ち着いた。失敗の種類が「自信のある誤り」から「書かれていません」に変わったのは、安全側への変化。車載でいえば、構成管理で、リリース済みの仕様と古い作業メモを同じ棚に置かないことに当たる
4. **evals そのものも間違える。** 期待する出典が狭く、正しい答えを2回「外れ」と判定した。目印の語が片方の指示にしかなく、試験が成り立っていないこともあった。evals も、人がレビューする成果物として扱う
5. **調整は、合わせ込みになる手前で止めた。** 8問に合わせて重みや質問を変え続けると、点数は上がっても、本当の質は分からなくなる。質問を増やすことは発展に回す
6. **無料枠の制約が、作り方を決めた。** 埋め込みは1分あたり3万トークンまで。429 で示された時間だけ待ち、本文ごとに埋め込みを保存して途中から再開できるようにした。`gemini-embedding-2` は、文の並びをそのまま渡すと1つにまとめて埋め込むので、文ごとに包む必要があった（返った数を確かめて気づいた）

TARA との対応：T-25 は、対策（C-29）のあとも「低減＋受容」のまま。答えを読むのは大人の開発者で、答えから操作を起こさないので、影響は「間違った答え」までに限られる。
