# イメージの署名と、生成物の来歴（16日目）

確認日：2026-11-02（KIDS-61）。脅威分析の T-27、C-30 に対応する。

## 1. コンテナイメージの署名と来歴

main に入ったイメージ（api、web）に、次を付ける。作業の定義は `.github/workflows/ci.yml` の `sign` と `verify`。

- 署名：cosign のキーレス署名。長く持つ秘密鍵を置かず、CI の身元で短い期限の証明書をもらう
- 来歴：`actions/attest`（GitHub の artifact attestations）。単体では SLSA Build Level 2
- 署名の対象：タグではなくダイジェスト（タグは付け替えられるため）

### 検証の結果

| 試験 | 道具 | 期待 | 結果 |
|---|---|---|---|
| 正しい署名 | cosign（CI） | 通る | 通った |
| 違うワークフローの身元（`other.yml`） | cosign（CI） | 断られる | `no matching CertificateIdentity found` |
| 署名を始める前のイメージ | cosign（CI） | 断られる | `no signatures found` |
| 正しい来歴（api、web） | `gh attestation verify`（手元） | 通る | 通った |
| 違うリポジトリの指定（api） | `gh attestation verify`（手元） | 断られる | `no attestations found` |
| 署名を始める前のイメージ（api） | `gh attestation verify`（手元） | 断られる | 来歴の取得が HTTP 404 |

CI の結果は、main の実行 41371882610（コミット 9b05ce3）で確かめた。

失敗の試験は、エラー文まで確かめる。通信の失敗でも cosign は失敗するので、終了コードだけでは「署名が理由で断られた」ことにならないため。最初の版は、実際のエラー文を確かめずに照合の文を書いたので、正しく断られたのに CI が赤になった（#92、#93）。

### 限界

- いまのところ、検証しているのは CI と手元だけ。AWS を片付けたので、pull して動かす本番の環境はない
- main のワークフローを書き換えられると、正しい身元で署名される。署名が示すのは「この CI で作った」ことで、「中身が安全」なことではない。PR と CI の必須化（ルールセット `protect-main`、`main-require-ci`）で守る
- CI 必須のルールが止められるのは、PR の時点で動く作業だけ。`sign` と `verify` はマージのあとで動くので、main の CI を別に確かめる
- マージのたびに、リポジトリ名、ワークフロー、コミット ID などが公開の透明性ログに残り、消せない

### 車載との対比

| 車載 | ここ | 違い |
|---|---|---|
| UN-R156（ソフトウェア更新の管理） | 署名、来歴、検証 | R156 は、更新の真正性と完全性を守る仕組みを求める。ここで扱うのはその技術の一部で、車両の型式認可や組織の管理は含まない |

## 2. 生成 AI の生成物の来歴

自作の短い指示だけで、4つの生成物を作った。子どもの写真・声・絵・名前、実在の人物は使っていない。生成物は `generated/`（Git の外）に置き、公開しない。

| 種類 | 作った場所 | C2PA | 判定 |
|---|---|---|---|
| 画像 | Gemini の画面（無料） | あり | Valid |
| 音楽 | Gemini の画面（無料） | あり | Valid |
| 話し声 | Gemini API（`gemini-3.8-flash-tts`、無料枠） | あり | Valid |
| 動画 | Google Flow（無料の1日50クレジット） | あり | Valid |

読むのに使った道具は `c2patool` 0.27.22（ハッシュを公式と照合し、リポジトリの外に置いた）。

4つとも、次の内容が共通だった。

- 署名者：Google LLC（Google Media Processing Services）
- 記録：`c2pa.created`（`trainedAlgorithmicMedia`）と、SynthID の透かしを入れた `c2pa.edited`

### 壊れ方の試験（画像のコピーで実施）

| 操作 | 結果 | 分かったこと |
|---|---|---|
| 1バイトだけ変える | `Invalid`（`assertion.dataHash.mismatch`） | 中身の改ざんを検出できる |
| 画像として読んで保存し直す | 来歴なし（`No claim found`） | 来歴は簡単に消える |

**C2PA は「付いていれば出どころが分かる」仕組みで、「付いていなければ AI ではない」とは言えない。** 付いていないものの判定には使えない。SynthID は、ピクセルや音そのものに入れる透かしで、C2PA を補う役割を持つ。今回は、手元で SynthID そのものの検出は試していない。

### 判定の注意

4つとも `signingCredential.untrusted`（署名の証明書を信頼できない）が出た。`c2patool` に信頼リストを設定せずに読んだためと考えているが、未確認。`Valid` は「署名と中身が合っている」ことで、「署名者を信頼できる」こととは別。車載で言えば、署名の計算は合っているが、ルート証明書を持っていない状態に近い。

### Adobe Firefly と Google Flow の比べ（2026-11-06）

Flow と同じ英語の指示（くじらが青い海を泳ぐ）で、Firefly の動画を1本作った。言葉の違いが混ざらないように、日本語の指示は使わなかった。

| 観点 | Google Flow（11-02） | Adobe Firefly（11-06） |
|---|---|---|
| 無料で作れる量 | 1日50クレジット | 動画2本まで |
| 作るのにかかった時間 | — | 約1分 |
| 長さと解像度 | — | 5.04秒、1920×1080 |
| 目に見える透かし | — | なし |
| 学習に使うかの設定 | — | 画面で見つからなかった（規約の確認は未実施） |
| 署名者 | Google LLC | Adobe Inc.（Adobe Firefly C2PA） |
| 生成の記録 | `c2pa.created` と、SynthID を入れた `c2pa.edited` | `c2pa.created` だけ。モデル名「Adobe Firefly Video Model 2」が記録される |
| AI 生成の印 | `trainedAlgorithmicMedia` | `trainedAlgorithmicMedia` |
| 署名の時刻 | — | Adobe の時刻認証局の時刻が付く（`timeStamp.validated`） |
| 判定 | `Valid`（`signingCredential.untrusted`） | `Valid`（`signingCredential.untrusted`） |

分かったこと：

- 2社とも C2PA と `trainedAlgorithmicMedia` を使っている。共通の規格なので、同じ道具（`c2patool`）で読み比べられる
- 違いは、映像そのものに入れる透かしが記録に出るかどうか。Flow の記録には SynthID が出たが、Firefly の記録には出なかった（入れていないとは言い切れない。記録に書かれていないだけ）
- Firefly の動画には、目に見える透かしがない。見た目では AI で作ったと分からず、手がかりは C2PA だけになる。C2PA は保存し直すと消えるので（上の壊れ方の試験）、公開するときは「AI で作った」と自分で書き添える
- 学習に使うかの設定は、画面で見つからなかった。業務で使う前に、規約と管理者の設定で確かめる
- 2社とも `signingCredential.untrusted` だった。原因は署名者ではなく、こちらに信頼リストがないこと、という見方が強まった

### サービスがなくなるリスク（Sora の終了）

OpenAI の Sora は、Web とアプリが 2026-04-26、API が 2026-09-24 に終了した（出典：OpenAI のヘルプ「What to know about the Sora discontinuation」、開発者向けの Deprecations のページ）。API の終了は、半年前の 2026-03-24 に知らされた。終了のあと、利用者のデータは消される。生成 AI のサービスは、数か月で終わることがある。業務で使うときは、次を先に決めておく。

- 作った物と、その来歴（C2PA）を自分の側に残す
- 別のサービスに乗り換えられるようにする。C2PA のように共通の規格を使うサービスを選ぶ
- 車載の部品と同じく、供給が止まったときの代わりを考えておく（ISO/SAE 21434 のサプライヤー管理、サポート終了の扱いに近い）

### 使うときの注意

- 肖像と声：実在の人物に似せたものを作らない。子どものデータは、規約の扱いに関係なく送らない（T-24）
- 著作権：既存のキャラクターや作品に似せない。生成物の権利の扱いは国とサービスで変わるので、公開や業務で使う前に規約と法務で確かめる
- ディープフェイク：来歴は「本物の証明」ではなく、出どころの情報の1つ。来歴が消えやすいので、重要な判断は別の経路でも確かめる
