# OWASP Top 10:2025 との照らし合わせ（えほんのサーバー保存 API）

- 対象：`backend/`（FastAPI + SQLite）と、それを呼ぶ `frontend/js/storage/server.js`・`index.js`。10日目（2026-10-21）、KIDS-35
- 前提：API は PC の中だけで使う（127.0.0.1 で待ち受け、既定は無効）。公開環境（GitHub Pages、Android アプリ、AWS 版）では使わない（T-08、C-12）
- 分類は OWASP Top 10:2025（公式リポジトリ OWASP/Top10 の `2025/docs/en` で確認）
- 判定：✅ 対策済み ／ ➖ 当てはまらない（理由つき） ／ ⚠️ 残る課題

| 分類 | 判定 | このAPIでの見方 | 対策と確かめ方 |
|---|---|---|---|
| A01 アクセス制御の不備 | ✅ | 認証はない（PC の中で、家族が使う前提）。代わりに「誰が届くか」を絞る | 127.0.0.1 だけで待ち受け。Host の許可リスト（DNS リバインディング）。書き込みは Origin が自分自身のときだけ（CSRF、T-18・C-22）。CORS の許可を出さないので、ほかのサイトは応答を読めない。ページの id は推測できない UUID。pytest：`test_host_and_static.py`、`test_origin.py` |
| A02 セキュリティの設定ミス | ✅ | 既定値が安全側か。不要な入口が開いていないか | 既定は無効で、`enabled` と正確に書いたときだけ有効。`/docs`・`/redoc`・`/openapi.json` は出さない（外部 CDN を読むため）。API の応答に `no-store` と `nosniff`。pytest：`test_disabled.py` |
| A03 ソフトウェアのサプライチェーンの失敗 | ✅ | Python の部品（本体15、開発用34）と、その版 | `uv.lock` で版とハッシュを固定。pip-audit で既知の脆弱性なし（2026-10-21）。Dependabot の対象に `backend/`（uv）を足し、更新は PR を人が確認してから取り込む（C-09） |
| A04 暗号の失敗 | ➖ | 通信は PC の中だけ（http://127.0.0.1）で、パスワードや鍵を扱わない | 外へ出す13日目の AWS 版では、そもそもこの API を使わない。HTTPS は13日目に nginx で行う |
| A05 インジェクション | ✅ | SQL、パス、保存したファイルを使った XSS | SQL はすべてプレースホルダ。列の名前は決まった SQL から選ぶ。ruff の S608 で検査（Hook でも自動で実行）。id は UUID 型で受ける。ファイルは種類の許可リスト（PNG、webm、ogg、mp4）と先頭バイトの確認。SVG・HTML は受け付けない。pytest：`test_validation.py` |
| A06 安全でない設計 | ✅ | 子どもの絵と声が、設定の誤りで外へ出ないか | 4つの独立した条件（フロントの判定、サーバーの環境変数、CSP、待ち受けと Host）。失敗したら IndexedDB に倒れ、サーバーには倒れない。脅威分析（T-08、T-18）から対策を決め、テストで確かめた |
| A07 認証の失敗 | ➖ | 認証の仕組みを持たない | PC の中だけで使い、届く範囲を A01 の対策で絞る。サーバーを PC の外に出す場合は、認証を先に作る（今の計画にはない） |
| A08 ソフトウェアやデータの完全性の失敗 | ✅ | 受け取ったデータを信じすぎないか。改ざんされた部品が入らないか | 申告された種類を信じず、中身の先頭バイトを見る。大きさの上限（絵 2MB、声 1MB、全体は Content-Length で先に判定）。知らない項目は保存しない。部品は A03 |
| A09 ログと警報の失敗 | ➖ | PC の中の1人用で、監視する人がいない | uvicorn の標準のアクセスログ（パスと状態だけ。絵と声の中身は出さない）。13日目の AWS 版で、nginx のログと合わせて見直す |
| A10 例外的な状態の誤った扱い | ✅ | 失敗したときに安全側に倒れるか。エラーで内部の情報を漏らさないか | 入力の誤りは理由の名前（`invalid-page` など）だけを返し、詳細は返さない。保存の取引は失敗したら巻き戻す（`ROLLBACK`）。フロントは、つながらない・遅い・形が違うときに IndexedDB にする。node:test：`storage-select.test.mjs` |

## /security-review の結果（10日目）

- 対象：#51・#52 の差分と Hook の変更
- 指摘1件（中、確信度 8/10）：CSRF。ほかのサイトから、えほんにページを足せた。読み出し・削除・上書きはできなかった → T-18 として脅威分析に足し、C-22（Origin の確認）で直した
- 問題なしとされたもの：読み出し、DNS リバインディング、SQL インジェクション、パス・トラバーサル、保存したファイルによる XSS、デバッグ情報、AWS で環境変数を設定し忘れたときの動き、Hook のコマンドの組み立て
- 設計上の注意：nginx の後ろに置くと、Host の許可リストが本物のホスト名を断る。そのとき `allowed_hosts=["*"]` にしない。AWS ではサーバー保存を有効にしない

## ISO/SAE 21434 との対応

OWASP Top 10 は「よくある弱点の一覧」で、21434 でいえば、TARA で脅威を洗い出すときの**チェックリスト**に当たる。一覧を当てはめただけでは、このアプリに特有の脅威（子どもの絵と声が設定の誤りで外へ出る T-08）は出てこない。脅威分析（threat-model.md）が主で、OWASP は抜けを探すための補助として使った。
