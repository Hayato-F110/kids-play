### 素材③の録り方（2026-10-16 に変更）

当初はスマホで画面録画する予定だったが、次の理由で、えほんの場面は Claude がPCで録り、実機はスクリーンショット1枚にした。

- スマホで録ると、マイクが部屋の音（家族の声など）を拾うおそれがある。PCの偽のマイクなら、合成音しか入らない
- 通知が映らず、何度でも同じように録り直せる。実機でファイルを操作しなくてよい（6日目の事故の対策 C-20）
- 「Androidアプリとして動く」ことは、③a の実機のスクリーンショットで見せる

録り方（スクリプトは `scripts/record-storybook/`。画面を直したら、14日目の前に録り直す）：

```powershell
python -m http.server 8000 --directory frontend   # 別のターミナルで動かしておく
npm run record:storybook                          # video/raw/ に素材③を作り直す
```

- 画面なしの Edge（Playwright）を、スマホの縦の大きさ（412×892）で動かし、えほんを操作する。利用者データは毎回新しく作るので、IndexedDB は空から始まる
- 偽のマイク（`--use-fake-device-for-media-stream` と `--use-file-for-fake-audio-capture`）に、ピアノと同じ作りの合成音（ド・レ・ミ・ソ、約3秒）を流す
- 映像は、ブラウザの画面の配信（CDP の screencast）からコマを受け取り、30fps に並べ直す。Playwright の録画機能は、早送りや巻き戻しの位置合わせができない webm になったため使わない
- 画面の配信は、拡大の設定（deviceScaleFactor）を無視して 412×892 で撮られる。画面を広くすると、えほんがタブレット用の配置に変わるため、この大きさのままにした
- 画面なしのブラウザは音を出さないので、音は別の WAV にした。録音の場面と紙芝居の場面に、同じ合成音を、映像と同じ時刻で置いてある。14日目に DaVinci で重ねる
- webm を DaVinci の無料版で読めない場合は、連番の JPEG（`03_storybook_frames/`）を読み込む
- 録ったあと、コマを抜き出して、自作の素材だけが映っていること、外への通信がないことを確かめた

素材①は 1920×1200（PCの画面の大きさ）で録れた。仕上がりは 1920×1080 なので、14日目の編集で、上下を切るか、縮めて左右に余白を入れるかを決める。全画面（F11）で録ったので、タブとアドレスバーは映っていない。

### タイトル画面の作り方（2026-10-28 に追加）

AIエージェントにコードから動画を作らせる流れを学ぶため、タイトル画面は Remotion（React で動画を書く道具）で作った。

```powershell
cd video/title
npm ci                # 初回だけ。書き出しのとき、Chrome Headless Shell（約280MB）が node_modules に入る
npm run still         # 1コマを out/title.png に書き出して、見た目を確かめる
npm run render        # 5秒の動画を out/title.mp4 に書き出す（1920×1080、30fps、H.264）
```

- アプリ（フロントエンド）はフレームワークなしの決まりなので、React を混ぜないように `package.json` を分けた
- 絵はアプリの自作SVG（`frontend/assets`）をそのまま読む。色はデザイントークンと同じ値
- ライセンス：個人は無料（従業員4人以上の会社は有料の Company License）。PC での書き出しは、ライセンスキーを設定しなければ利用状況を送らない
- zod：Remotion が固定する 4.5.4 には、メモリを使い果たす脆弱性がある（4.6.6 で修正）。`overrides` で 4.6.7 に上げた。Remotion は版の不一致の警告を出すが、書き出しはできる。Remotion が zod を上げたら、`overrides` を外す
