# 用語集

学習の中で出てきた用語を、車載ソフトや C との例えつきでまとめる。日を追うごとに書き足す。

## 10日目（2026-10-21）：FastAPI、保存の API

### バックエンド

| 用語 | 意味 | 車載・C などで例えると |
|---|---|---|
| API | プログラム同士がやり取りする窓口。このプロジェクトでは `/api/pages`（えほんのページの保存・読み出し・削除） | 診断サービスの要求と応答の決まり |
| FastAPI | Python で Web の API を作るための部品（フレームワーク）。`@app.post("/api/pages")` の下に関数を書くと、その URL の窓口になる | 診断サービス（UDS）のサーバー側の実装。ID ごとに処理を並べる |
| Pydantic | 入力の型と範囲を検証する部品。「`voiceMs` は 0 以上の整数」と書くだけで、違う値を自動で断る | 構造体の定義から作る、受信データの範囲チェック |
| uvicorn | FastAPI のアプリを、実際にネットワークで待ち受けさせるサーバー本体 | 通信スタックの受信処理 |
| SQLite | ファイル1つで動く小さなデータベース | 不揮発メモリ上の簡易データ管理 |
| 取引（`BEGIN IMMEDIATE`） | 「数える・決める・書く」を1つにまとめ、途中で割り込まれないようにする | 割り込み禁止区間 |
| uv | Python の部品の導入と版の固定（`uv.lock`）をする道具 | ツールチェーンの版管理 |
| pytest | Python のテストの道具 | 単体テストの枠組み |
| ruff | Python の整形と静的解析の道具（セキュリティの S ルールを含む） | MISRA チェッカー＋clang-format |
| fail-safe（既定は無効） | 設定を忘れたときに、安全な側（保存しない側）に倒れるようにする | 異常時に安全側の状態へ遷移する |

### セキュリティ

| 用語 | 意味 | ISO/SAE 21434・車載との対応 |
|---|---|---|
| CSRF | ほかのサイトのスクリプトが、利用者のブラウザを使って勝手に書き込みの要求を送る攻撃 | なりすました送信元からの要求 |
| Origin | 要求を送ったページの出どころ。ブラウザが書き込みの要求に付ける | 送信元 ID |
| CORS | ほかのサイトに、応答を読ませるかどうかの決まり。書き込みの送信そのものは止めない | 読み出しのアクセス制御 |
| DNS リバインディング | よそのサイトの名前を 127.0.0.1 に向けて、PC の中のサーバーを読ませる攻撃。Host の確認で防ぐ | 宛先の偽装 |
| OWASP Top 10 | Web の代表的な弱点の一覧。TARA で脅威を洗い出すときのチェックリストとして使った | 脅威カタログ |
| pip-audit | Python の部品の既知の脆弱性を調べる道具 | 部品の脆弱性の監視 |

### Claude Code

| 用語 | 意味 |
|---|---|
| `/security-review` | 変更を、安全性の観点だけで別の担当が読み、確信度の低い指摘を捨ててから報告する |
| `/code-review` | 変更を、正しさ・簡潔さの観点で読み、指摘を一覧で返す |
| `claude -p`（ヘッドレス実行） | 会話を開かずに、決まった頼みごとを1コマンドで実行する。結果を決めた形（JSON）で受け取れる |

## 11日目（2026-10-22）：WSL、Docker、CI

### Linux・WSL

| 用語 | 意味 | 車載・C などで例えると |
|---|---|---|
| WSL2 | Windows の中で本物の Linux を動かす仕組み | PC の中の仮想 ECU |
| ディストリビューション | Linux の種類（Ubuntu、Debian など） | 同じカーネルを使う OS の製品版 |
| Ubuntu 24.04 LTS | Ubuntu の長期サポート版（2029年まで更新） | サポート期間の長い量産向けの版 |
| `.wslconfig` | WSL が使うメモリや CPU の上限を決めるファイル | リソースの割り当て表 |
| `sudo` | 管理者（root）として1回だけ実行する | 診断の特権セッション |
| `apt update` / `upgrade` | 部品の一覧の更新 / 部品を最新にする | ソフトの更新の確認と書き換え |
| root | Linux の最上位の管理者 | 何でもできるスーパーバイザーモード |
| uid | ユーザーの番号（root は 0） | タスクの ID |
| パーミッション（`rwx`） | 読む・書く・実行するの許可 | MPU の保護設定 |
| systemd | サービスを起動・管理する仕組み | タスクの起動管理 |

### Docker

| 用語 | 意味 | 例え |
|---|---|---|
| Docker | アプリと動く環境を箱に詰めて、どこでも同じに動かす道具 | – |
| イメージ | 箱の中身の固まり（変更できない） | フラッシュイメージ（hex） |
| コンテナ | イメージを動かしている実体 | 電源を入れた ECU |
| Dockerfile | イメージの作り方 | ビルドスクリプト |
| 2段のビルド（マルチステージ） | 作る段と動かす段を分け、道具を残さない | 開発用ツールを量産品に載せない |
| ベースイメージ | 土台にするイメージ（python、nginx） | 土台の OS・BSW |
| Alpine | 小さい Linux。部品が少ない | 必要最小限の構成 |
| ダイジェスト（`sha256:…`） | 中身の指紋。1ビット違っても変わる | ソフトのハッシュ値 |
| タグ（`1.30.6` など） | 版の名前。付け替えられる | 版のラベル |
| docker compose | 複数のコンテナをまとめて起動する | 複数 ECU の構成表 |
| `.dockerignore` | イメージに渡さないファイルの指定（このプロジェクトでは許可リスト方式） | 出荷物に入れるファイルの一覧 |
| Docker Desktop | Windows で Docker を使うためのアプリ | – |
| docker グループ | docker を使えるユーザーの集まり。実質 root | 特権を持つ人の一覧 |

### Web サーバー

| 用語 | 意味 | 例え |
|---|---|---|
| nginx | Web サーバー。ファイルを配り、裏のサーバーへ中継する | ゲートウェイ ECU |
| リバースプロキシ | 受けた要求を裏のサーバーへ中継する | ゲートウェイの転送 |
| `limit_except` | 許すメソッド（GET など）以外を断る nginx の設定 | 受け付ける ID のフィルター |
| `Host` ヘッダー | 要求の宛先の名前 | 宛先アドレス |
| MIME タイプ | ファイルの種類の表示（`application/manifest+json` など） | データ形式の識別子 |

### CI/CD・GitHub

| 用語 | 意味 | 例え |
|---|---|---|
| CI | 変更のたびに自動でテスト・ビルドする | 夜間ビルドと自動テスト |
| GitHub Actions | GitHub の CI の仕組み | Jenkins |
| ワークフロー（`ci.yml`） | CI の手順を書いたファイル | ビルドジョブの定義 |
| ジョブ | ワークフローの中の作業のまとまり（test、scan、push） | ジョブの1段 |
| GHCR | GitHub のイメージ置き場（レジストリ） | リリース物の保管サーバー |
| `GITHUB_TOKEN` | ワークフローに自動で渡る、期限つきの鍵 | 一時的なアクセス権 |
| `permissions` | ワークフローの鍵に与える権限 | アクセス権の設定 |
| 成果物（artifact） | CI が作ったファイルの保管（SBOM など） | ビルドの出力物 |
| コミット ID で固定 | 部品をタグでなく中身の指紋で指定する | 版をハッシュで固定 |
| Dependabot | 部品の新しい版を知らせる PR を自動で作る | 部品の更新の監視 |
| `@claude` | PR や Issue のコメントで Claude を呼ぶ仕組み（GitHub Actions の上で Claude Code が動く） | CI に組み込んだ解析 |
| GitHub App | GitHub と連携するアプリ。権限をまとめて渡す | – |

### セキュリティ

| 用語 | 意味 | ISO/SAE 21434・車載との対応 |
|---|---|---|
| 脆弱性（CVE） | 公開された弱点の番号（例：CVE-2022-22822） | 既知の脆弱性情報 |
| CRITICAL | 重大度の最上位 | 影響度・高 |
| Trivy | イメージの部品の脆弱性を調べる道具 | 脆弱性スキャン |
| SBOM | ソフトの部品表 | 部品表（UN-R155 のサプライチェーン管理） |
| CycloneDX | SBOM の書式の1つ | 部品表の様式 |
| サプライチェーン攻撃 | 取り込む部品に悪意あるコードを入れる攻撃 | サプライヤー経由の攻撃 |
| trivy-action の乗っ取り（CVE-2026-33634） | 2026年3月、Trivy の CI 部品のタグが付け替えられ、秘密情報を盗んだ事件 | 正規部品の改ざん |
| immutable リリース | 公開後に中身を書き換えられない公開方法 | 改ざんできない出荷物 |
| 最小権限 | 必要な権限だけを渡す | 最小権限の原則 |
| capabilities | root の権限を細かく分けたもの。このプロジェクトでは全部外した | 特権の細分化 |
| no-new-privileges | あとから権限が増えるのを禁止 | 権限昇格の防止 |
| 読み取り専用（read_only） | ファイルを書き換えさせない | 書き込み保護 |
| DoS | 大量の要求で動けなくする攻撃 | バスの占有 |
