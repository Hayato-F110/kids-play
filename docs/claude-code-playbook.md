# 仕事で使えるClaude Code活用ガイド（QCD別）

毎日1つ、Claude Codeの機能を実際に使い、効果と仕事での使いどころを記録した。14日目（2026-10-28）に仕上げた。まず「QCD別のまとめ」を読み、詳しくは「機能ごとの記録」を見る。

- 機能の説明は公式ドキュメント（https://code.claude.com/docs）と /release-notes に基づく
- QCD：**Q**＝品質、**C**＝コスト（トークンと手戻り）、**D**＝スピード

## QCD別のまとめ

14日間で使った機能を、効いた順に並べた。仕事に持ち帰るときは、上から取り入れる。

### Q：品質を上げる使い方

- **守りは仕組みで重ねる**：CLAUDE.md（文章のルール）→ settings.json の deny / ask → Hook（実行前に止める）→ サーバー側の保護（ブランチ保護）の順に重ねる。1つの層（AI の注意、自動の判定）を信じない。6日目の事故で、文章のルールだけでは止まらないことが分かった
- **作った会話とは別の目でレビューさせる**：サブエージェント（privacy-reviewer、design-reviewer）、`/security-review`、`/code-review`。作った本人（AI）が見落とした指摘が、毎回見つかった（CSRF、Service Worker と CSP、写り込みなど）
- **テストを先に書かせる**：不具合も、まず失敗するテストで再現させてから直させる。「直った」を機械で確かめられる
- **事実と判断を分けさせる**：「公式の仕様に基づいている？」「確かめたこと／確かめていないこと」を聞く。記憶や訳による誤り、隠れた判断に気づける
- **出したものを実測させる**：push・公開・設定のあとに、外から見た実際の状態を測らせる（GHCR の公開範囲、Jira の更新結果）
- **失敗したら、推測せず実際の値を見させる**：OIDC の `sub` のように、仕様の例と実際の値は違うことがある

### C：コスト（トークンと手戻り）を下げる使い方

- **繰り返す指示は道具にする**：カスタムコマンド、スキル、Hook、`claude -p`。「整形して」「この観点で見て」を毎回書かない
- **先に計画と見本を作らせる**：Plan モードで実装前に差を見つける。見た目の作業は「仕上がりの見本」を先に作らせる。手戻りが大きく減った
- **会話を区切る**：作業の区切りで `/clear`。`/usage` と `/context` で、何が使用量を増やしているかを数字で見る（長い会話、長時間の会話、画像）
- **画像と長い出力を減らす**：画像は必要な部分だけ。長いログはファイルにして、必要な行だけを読ませる
- **調べ物はサブエージェントへ**：途中経過が本体の会話に残らない

### D：スピードを上げる使い方

- **待ち時間に並べる**：レビューや CI はバックグラウンドで動かし、その間に次の作業を進める。git worktree で別の課題を同時に進める
- **画面の操作を AI に任せる**：画面なしのブラウザ（Playwright MCP）で、確認と画像化まで自動で行う。人は音と操作感だけを確かめる
- **API で読める確認は任せる**：GitHub の設定、Jira の課題、CI の結果は、画面を開かずに読ませる（書き込みは人）
- **権限を適切に広げる**：PC 内で戻せる操作は allow、外部・削除・main への push は ask。確認待ちを減らしつつ、危険な操作の承認は残す
- **プラグインで配る**：スキル・レビュー担当・Hook をまとめて、チームに同じ守りと手順を配る

## 仕事に持ち帰るときの注意

- 会社のセキュリティ規程と、生成AIの利用ルールを先に確認する
- 機密コードや顧客情報を扱うフォルダは deny に入れる
- AIを動かすPCに、壊れると困るものをつながない。つなぐ必要があるときは、届く範囲、バックアップ、人の承認の3つを先に決める（下の「事故の記録」）
- AIに、削除を任せない。対象を変数で組み立てる削除は、実行の前に、組み立てた対象を表示させて人が見る
- 外部サービス（チケット、チャット、クラウド）の MCP は、読むだけから始める。書き込みは、サービス側と Claude Code 側の二重で止める
- 画面の写しを AI やリポジトリに渡す前に、秘密の値・個人の情報（壁紙、通知、タブ、アドレスバー）が写っていないかを見る。写っていたら、作り直す（秘密の値）か、外へ移す（画像）
- 一括の操作（CSV の取り込み、一括変更）は、まず1件で試す。失敗しても消さずに、紐づけて閉じて記録を残す
- 会社の規程と承認の範囲で使う。ここで作った設定（Hook、プラグイン）は、社内に持ち込む前の「型」として扱う

## 事故の記録：実機の画像をすべて削除した（6日目、2026-10-13）

事実を、そのまま残す。原因はClaudeの操作で、学習者の指示や操作の誤りではない。

### 何が起きたか

| 順 | 出来事 |
|---|---|
| 1 | Androidアプリの画面を確かめるために、Claudeが adb で、座標を指定したタップと、端末全体の画面の撮影を続けて送った |
| 2 | 端末は横向きで、Claudeは縦向きの座標を使っていた。画面を見ずに続けたので、アプリが閉じ、ホーム画面の別のアプリを起動した。その画面を撮影し、画像を会話に読み込んだ（1回目の誤操作） |
| 3 | 方法を、アプリの中身だけを取り出す確認（WebView のデバッグ接続）に変えた |
| 4 | 「ほぞん」の確認で、端末に白紙の画像が1枚できた。Claudeが、それを消すコマンドを端末に送った |
| 5 | コマンドの誤りで、消す対象のIDが空になり、「この1件」ではなく「画像の一覧すべて」の削除になった。内蔵と microSD の画像（1,900件以上）が消えた（2回目の誤操作） |
| 6 | 端末のバックアップはオフだった。内蔵の分は、保存領域が暗号化されているので復元できない。microSD の分は、カードリーダーで直接読めば、復元できる見込みがある |

### 原因

| 層 | あるべき守り | 実際 |
|---|---|---|
| Claudeの判断 | 端末で削除のコマンドを使わない。使うなら、対象を表示して確かめてから | 確かめずに実行した（根本の原因） |
| コマンド | – | PowerShell で `-match` を2回続け、1回目の結果（ID）が2回目で上書きされた |
| Claude Code の権限 | 危険なコマンドは、実行の前に止まる | 自動で可否を決めるモードが、このコマンドを通した。deny と Hook は、PC内の秘密情報だけを対象にしていた |
| 端末 | 外からの操作を制限する | USBデバッグを許可すると、PCからの操作をほぼ無条件に受け入れる。削除は、ごみ箱を通らない |
| バックアップ | 消えても戻せる | オフだった |

### 対策

- adb 経由の削除・書き換え、入力の送信、端末の画面の撮影を deny にした。`adb shell` は、毎回、人の承認を求める（`.claude/settings.json`）
- Claudeは、実機で、削除・書き込み・座標のタップ・端末全体の撮影をしない。確認で端末に作ったものの後片づけは、人が行う
- 脅威分析に、資産A6（アプリと関係のない個人のデータ）、脅威T-16（AIエージェントの誤操作）、対策C-20を追加した。これまでは外からの攻撃者だけを想定していて、内側で動くエージェントの誤りを脅威として扱っていなかった

### 仕事に持ち帰ること

- 「プロジェクトのフォルダの中で動く」は、ファイルの読み書きの話。コマンドは、PCにつながるものすべてに届く。実車、試験装置、書き込みツール、共有サーバーをつないだPCでは、同じことが起こりうる
- 機能安全の考え方がそのまま当てはまる。1つの層（AIの注意、自動の判定）を信じず、独立した層（deny、人の承認、バックアップ）を重ねる。取り返せない操作ほど、人の承認を残す
- 事故のあとは、先に事実と影響の範囲を確かめ、上書きを止める（今回は、microSD への書き込みを止めた）。復元の見込みは、保存の方式（暗号化の有無、削除のしくみ）で決まる
- AIの「確かめた」は、何をどう確かめたかまで聞く。AIが端末に作ったもの、消したものは、記録に残させる
